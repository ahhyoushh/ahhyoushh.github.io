pls move on

jun 2026

i failed my competitive exams. then iitk announced b.cyber, an undergrad cybersecurity programme that was, supposedly, for people like me: students who didn't do well in jee main, or didn't sit it. shortlisting was meant to be hackathon / portfolio based (with a jee main percentile cutoff as well, of course). my percentile was bad, and i knew i wouldn't make the list. i registered anyway.

the captcha on the registration page was generated and checked inside the browser. on the portal for a bachelor's in cyber security. yes, ironic. moving on.

no prior cybersec background here, just a network tab. the short version:

  1. the captcha is realperson.js, a jquery plugin from 2009. it draws the text and validates it client-side.
  2. one prompt to claude sonnet (the visible DOM plus the plugin source) gave me a console snippet that decodes it.
  3. the otp rate limit was a JSESSIONID cookie. clear it, get a fresh quota. a small playwright script does that in a loop.
  4. i reported it to pingala@iitk.ac.in with the scripts. the official inbox never replied, so i forwarded it to someone at c3i iitk, who got it fixed within 24 hours: an image captcha and server-side verification, which is what i'd suggested.

thread on x is here.

what gave it away

after filling the form, the first thing i noticed was that regenerating the captcha was instant. no wait, no spinner. so i opened the network tab, and it was all client-side: a jquery plugin generated a character matrix in the browser and validated it in the browser. as far as i could tell the server never got a say. the fix they shipped later was server-side verification, which tells you what was missing.

the plugin lives at plugins/form-validator/jquery.realperson.js. they've since stopped referencing it, but when i first wrote this up the file was still sitting there, publicly.

it picks 6 random letters, draws each one as a 7-row grid of * characters, and on submit stuffs a hash of the real text into a hidden field to compare against. that hash is djb2:

function hash(value) {
    var hash = 5381;
    for (var i = 0; i < value.length; i++) {
        hash = ((hash << 5) + hash) + value.charCodeAt(i);
    }
    return hash;
}

and this is the letter A, taken straight from the plugin's lookup table:

   *
  * *
  * *
 *   *
 *****
*     *
*     *

the whole "captcha" is 26 of those. decoding it is a string match, not a vision problem.

the decoder

i didn't write this part. i pasted the DOM and the plugin into claude sonnet, asked for a console snippet that decodes the captcha, and it did. no surprises. it fills the input for you. collapsed by default, click on ' + '.

the otp limit was worse

and of course i got otp rate-limited. but the limit was tied to a JSESSIONID that the server handed my browser and then trusted back from a cookie. clear the cookie and you're a new person. lmao.

so: a small playwright script, a fresh browser context per session, a new registration session each time, a new quota each time. it worked, and the otps arrived.

the otp bypass, on video.

honestly this is the more serious finding. a captcha is a speed bump. a rate limit that resets when you delete a cookie isn't a rate limit.

the obvious next question is whether their server falls over holding a pile of pending otps, or whether their mail server starts flagging the volume. i didn't test either one. it isn't my server.

telling them

i emailed pingala@iitk.ac.in with both scripts and two suggestions: an image-based captcha, and server-side verification. no reply, not even an acknowledgement.

so i forwarded the whole thing to someone at c3i iitk. he fixed it within 24 hours, with both of the things i'd suggested. that's the part that actually worked: not the inbox that was meant to receive reports, but one person who read the email and did something about it.

scope, for the record: one portal, one registration flow, everything done from a browser. i didn't look at the backend, so i can't say what else is wrong back there.

pls move on

the programme i applied to wouldn't have taken me on my percentile. its front door turned out to be a 2009 jquery plugin and a cookie. i'm in college now, just not that one.

a rank is one exam on one day. this was a thing i actually did. i'd rather be good at the second one.

pls move on, me.
